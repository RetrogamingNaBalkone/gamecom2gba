# Правила проекта

- В каждом корневом каталоге файлы игры храним в подпапке с её именем, например `duke3d/`. Общие компоненты остаются на уровне корневого каталога. Скриншоты для README раскладываем по играм в `docs/images/`.

- В Git храним собственный код, описания форматов, тесты и нарисованную для порта графику. Оригиналы пользователя находятся в `originals/`. Дампы BIOS, ROM, декомпиляцию, извлечённые картинки, звук, игровые снимки и готовые образы оставляем вне Git. Исключение — скриншоты для README в `docs/images/`.
- Репозиторий локальный. Сборочное окружение и проекты Ghidra помещаем в `build/`, готовые сборки — в `dist/`. Каждый скрипт удаляет созданные им временные файлы, включая случай ошибки.
- Используем общие установки Zig, mGBA и Ghidra. Дополнительные инструменты устанавливаем для пользователя или системы, чтобы их могли использовать следующие проекты.
- Каждый порт нативный. Пользователь подаёт собственный ROM, при необходимости — BIOS. До извлечения ресурсов сверяем содержимое с белым списком. Общие инструменты и графические преобразования должны подходить для следующих игр.
- Исследуем код в Ghidra. Устройство game.com и палитру сверяем с MAME. Для графики используем возможности GBA, отдельные слои и спрайты. Покадровое копирование фреймбуфера game.com исключено. Частота отрисовки независима от игрового времени.
- При анализе каждого картриджа обязательно ищем неиспользуемые звуки, графику, уровни и меню. Проверяем ссылки из кода и таблиц, включая условия доступа к секретному контенту. В документации игры фиксируем результат по каждой категории. Для находок указываем ID или адрес в ROM и основание вывода. Если ресурс не встретился при прохождении, а его достижимость по коду остаётся неясной, отмечаем его как «использование не подтверждено».
- Исходные 200×160 пикселей располагаем по центру экрана 240×160. По бокам — полосы цвета корпуса, слева вертикальная game.com, справа tiger.
- Кнопки назначаем по игровым действиям. Для действия, доступного только касанием, описываем варианты и ждём решения пользователя. Выбранное управление описываем в документации игры.
- В порте Indy 500 машины D и E доступны при первом открытии штатного экрана выбора машины. В порте Mortal Kombat Trilogy Ermac и Noob Saibot доступны при первом открытии штатного экрана выбора бойца. Проверяем, что их можно выбрать на чистом сохранении без ввода кодов.
- Эталон поведения — поддерживаемая версия картриджа game.com. Перед исправлением спорной механики воспроизводим один сценарий на оригинале и в порте. Записываем начальное состояние, последовательность действий и результат в каждой версии. Намеренные отличия и их причины описываем в документации игры.
- Для первого играбельного этапа выбираем короткий маршрут от запуска через обычный игровой интерфейс до проверяемого результата, например выхода с уровня. Проходим этот маршрут на оригинале и в порте.
- Изменения, которые могут заметно увеличить размер ROM или время отрисовки кадра, обосновываем замерами. До и после изменения записываем размер образа, а на одной и той же тяжёлой сцене измеряем частоту видимых обновлений и темп выбранного игрового действия.
- В статусе порта указываем, какой сценарий проверен и в какой среде. Отдельно описываем проверки в эмуляторе и на физической GBA, известные расхождения с оригиналом и сценарии, которые ещё предстоит проверить.
